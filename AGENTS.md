## Learned User Preferences

- Dark buttons over a gradient must use a solid-color hover (e.g. `hover:bg-black`), never `hover:opacity-*` — opacity lets the purple gradient bleed through and looks "purplish".
- Do not add hover transforms (translate/scale "move up") to buttons unless the design explicitly shows them.
- When asked for a PR title/description, return copy-pasteable markdown matching the repo's GitHub PR template and include the specified local commit SHAs.
- Every clickable button (and button-like control: `Button`, raw `<button>`, CTA links, selects, checkbox labels) must include `cursor-pointer`, with `disabled:cursor-not-allowed` when disabled.
- When matching a design PNG, apply only the requested visual fixes — do not invent unrelated styling changes the user did not ask for (e.g. do not recolor all borders black unless the design shows that).
- Toasts use Sonner styled with design tokens; always position bottom-right; use semantic colors for success (green), error (red), and info (yellow).
- Profile resume section: do not show "Resume on file" (or similar green status) text; when a resume exists, offer View (in-app PDF preview / modal that can open in a new tab) and Download with a proper `.pdf` filename — never navigate raw private storage URLs that trigger blocked popups or extensionless downloads.
- When architecture docs only type a column as `jsonb` without nested fields, derive the object shape from the feature's design PNG (e.g. `context/designs/profile.png` for `work_experience`), not invent fields independently.
- Profile form chrome: skills/industry chips use purple/accent styling; "Extract from Resume" must match "Save Profile" button styling and stay equal-sized with **Generate Resume** (short label `Generate Resume` + lucide icons — avoid long labels that overflow); give Extract / Generate / Clear all fields / Save Profile suitable lucide icons; "Clear all fields" is a red destructive control with a full solid-color hover fill (never black or partial coverage) and clears every field except the uploaded resume; checkbox labels must vertically align with the control; unchecked checkboxes need a visible dark (not black) border.
- OpenRouter BYOK UI copy must be end-user friendly (not developer jargon about quotas/encryption); while BYOK keys are saved, never soft-fall back to platform env keys (that would bypass app rate limits) — tell users to update or remove keys to use Job Flow quota. BYOK skips the per-user Resume AI quota only — shared **IP** network limits still apply.
- **shadcn first:** always use registry components (`Select`, `Checkbox`, `Button`, …) when available; do not introduce native `<select>` / checkbox / parallel wrappers. Keep Job Flow token styling on shadcn triggers. Keep `Select` controlled for its lifetime (use `""` or a sentinel, never `undefined` ↔ string). `Button asChild` (Radix Slot) requires exactly one React element child — wrapping multiple children (e.g. icon + text fragments) throws “Slot failed to slot onto its children”.
- Shared `Navbar` on all pages (home structure + lucide icons for Dashboard / Find Jobs / Profile, active underline); logo always goes to `/` and the homepage must stay reachable with no bounce to `/dashboard`. AuthGuard pages (including `/find-jobs/[id]`) must use that shared Navbar only — never nest a second Navbar (double bar on refresh/loading). Marketing CTAs “Get Started” / “Find Your First Match” go to `/login` when signed out and `/find-jobs` when signed in; Navbar CTA is **Get Started** → `/login` when signed out, and a profile **Avatar** dropdown (hover open, click to pin; show profile photo when available — not initials-only; Profile + Sign out with `user_signed_out` / analytics reset / redirect `/`; compact AI usage + OpenRouter keys panels) when signed in.

## Learned Workspace Facts

- Stack is Next.js 16 (App Router) + React 19 + Tailwind CSS v4 + TypeScript 5. There is NO `tailwind.config.js`; design tokens live in `app/globals.css` under the `@theme` directive as CSS variables (the single source of truth), with `--jp-*` aliases for shadcn mapping. Use token utilities (`bg-surface-muted`, `border-l-accent`, `bg-overlay-dark`, `text-text-primary`, `border-border`, `var(--color-accent)` / `--color-accent-dark`), never raw hex or default Tailwind color classes. With `next/font`, use an intermediate `--font-inter` variable and `@theme inline { --font-sans: var(--font-inter); }` — never set `--font-sans` to static `"Inter"` in `@theme`. **UI primitives are shadcn/ui first** (`components.json`, `npx shadcn@latest add …`); keep Job Flow colors. Always use the registry component (`Select`, `Checkbox`, `Button`, `Input`, …) when one exists — never native `<select>`, raw `<button>`, or `<input type="checkbox">` as a substitute. InsForge's generic "keep Tailwind on 3.4" guidance does NOT apply — never downgrade. App unit/integration tests use Vitest (`vitest.config.ts`; `npm test` / `npx vitest run`).
- InsForge is the chosen backend (`@insforge/sdk`, base URL `https://9d5rf9jh.ap-southeast.insforge.app`); Feature 04 schema is provisioned. **`@insforge/ssr` does not exist** — never reference `createBrowserClient`/`createServerClient`. **Feature 06 profile mutations use the browser SDK** (`lib/profile.ts`) with the session JWT so RLS applies — not Server Actions / `@insforge/sdk/ssr`. Agent API routes (Feature 10) still need JWT forwarding for server writes. **`@insforge/react` is deprecated** — use a custom `AuthProvider`/`useUser()` wrapping `@insforge/sdk`. Use the SDK for app logic (auth/DB/storage/AI/functions) and InsForge MCP tools for infra (schema, buckets, functions, deploy). Call `fetch-docs`/`fetch-sdk-docs` before writing any InsForge code. SDK ops return `{ data, error }`; DB access is `insforge.database.from("table")` (not `insforge.from(...)`); DB inserts need array format `[{...}]`; serverless functions have a single endpoint (no nested routes).
- Auth (Feature 02) is **browser-first**: custom `AuthProvider` + client-side `AuthGuard` redirects; **no `middleware.ts`**. OAuth via `insforge.auth.signInWithOAuth`; `/callback` relies on SDK auto-detecting `insforge_code` through `getCurrentUser()`. Google/GitHub OAuth must be enabled in the InsForge dashboard with `http://localhost:3000/callback` in `allowedRedirectUrls`. **Bearer calls to Next API routes** (`requireAuth`) must use `authedFetch` / `getAccessTokenForApi` (`lib/authed-fetch.ts`, `lib/auth-access-token.ts`) — never raw `getValidAccessToken()` alone; 401 triggers one force-refresh retry; `AuthProvider` also refreshes on focus/visibility + interval. Protected-page loading uses `Navbar` + structural shadcn `Skeleton` fallbacks (never full-viewport spinner-only); skeletons must mirror the real page layout (no phantom blocks such as a profile-image circle that is not on `/profile`); Profile sections that fetch independently (usage, OpenRouter keys, resume preview) skeletonize in place.
- PostHog (Feature 03) initializes in `instrumentation-client.ts` (Next.js 16 client hook) with `/ingest` reverse-proxy rewrites in `next.config.ts`. User identity wired in `AuthProvider` (`identify` on session load, `reset` on sign-out). Env vars: `NEXT_PUBLIC_POSTHOG_PROJECT_TOKEN`, `NEXT_PUBLIC_POSTHOG_HOST` (documented in `.env.sample`).
- Feature 04 (Database Schema): versioned SQL in `insforge/migrations/` (`001_initial_schema.sql`, `002_harden_schema.sql`, `003_byok_openrouter_keys.sql` — do not re-run `001` on an existing DB); tables `profiles`, `agent_runs`, `jobs`, `agent_logs` with ownership RLS; `profiles.openrouter_keys_enc` stores encrypted BYOK OpenRouter keys (never exposed on client `Profile` / `saveProfile`); private `resumes` bucket with object key `{user_id}/resume.pdf` (never prefix the key with the bucket name — RLS checks the first path segment against `auth.uid()`); TypeScript models in `types/index.ts` (`Profile.education` is `Partial<Education>` because signup stubs default to `{}`). Nested JSONB shapes not fully specified in architecture (e.g. `work_experience`) are taken from `context/designs/profile.png`.
- Feature 05/06 Profile: UI from `context/designs/profile.png` under `components/profile/` (AuthGuard-wrapped `/profile`); loads/saves via `lib/profile.ts` (browser InsForge client); `is_complete` from `getProfileCompletion`; resume PDF ≤5MB to `resumes` with upload-first then cleanup of prior keys (never delete-before-upload); private-bucket View/Download use signed/download URLs for PDF preview (modal/new tab) and `.pdf` download — not raw private object URLs; InsForge may auto-rename on key collision — treat storage `remove` "Object not found" as benign; PostHog `profile_completed` on incomplete→complete; save feedback via Sonner toasts. Cover letter tone omitted from UI. **OpenRouter BYOK** via `OpenRouterKeysSection` → `GET/POST/DELETE /api/profile/openrouter-keys` only (not `saveProfile`); UI adds one key at a time; validate `sk-` format + live OpenRouter `GET /api/v1/key` before encrypt; max 5 keys; AES-256-GCM with `BYOK_ENCRYPTION_SECRET`; masked `last4` only in UI; no platform-key soft fallback while BYOK rows exist.
- Feature 07 AI Profile Extraction: **Extract from Resume** on `/profile` after upload → client Bearer JWT + PDF → `POST /api/resume/extract` (`lib/api-auth.ts` + `pdf-parse` + AI SDK `generateObject`). Model via `lib/ai/provider.ts`: OpenRouter `openrouter/free` only; env `OPENROUTER_API_KEYS` (comma-separated, whitespace around commas trimmed) or `OPENROUTER_API_KEY`, plus `AI_PROVIDER`, `AI_MODEL`. `withOpenRouterKeyFailover` rotates within the active list (platform env **or** user BYOK override) only on **OpenRouter** rate-limit/quota errors — never mid-request between BYOK and platform lists; Job Flow Redis abuse 429s abort before the AI call (no key rotation). **Shared** per-user Resume AI pool (`resume-ai:{userId}`) with Generate, Find Jobs, **and** Company Research: windows from `RESUME_AI_RATE_LIMIT_PER_MINUTE|HOUR|DAY`; hits when `REDIS_URL` is set; **429 only when `APP_ENV` is production/prod**; skipped entirely for BYOK. Separate **IP** pool `resume-ai-ip:{hash}` (`RESUME_AI_IP_RATE_LIMIT_*`, defaults 10/45/120) on the same four routes — **1 hit per request** (Find: once per search; Research: once per Research Company); always applies when Redis is set **including BYOK**; also 429-only in production; not shown in usage UI. **Extract/Generate record user + IP usage only on success** — never increment minute/hour/day counters on rate-limit 429s or failed runs. `GET /api/resume/usage` + profile/Navbar usage UI (hidden in development or with BYOK). Extraction must recover LinkedIn/portfolio/GitHub from PDF hyperlink annotations (not only visible text), fill sparse model output with resume-based fallbacks, reject salary-only “success”, and merge into form state (`mergeExtractedIntoProfile`) — user reviews then saves manually. Play `/sounds/completion.mp3` via `lib/completion-sound.ts` (Howler) after successful Extract / Generate / Find Jobs / Research.
- Feature 08 Resume PDF Generation: **Generate Resume** (short label + `FileText` icon) — save-first dirty gate (`lib/profile-dirty.ts`) then `POST /api/resume/generate`. Server loads saved profile, AI polish at temp `0.7` (same OpenRouter free + key failover / BYOK override); free models may return markdown instead of JSON — heal prose into schema, then fall back to deterministic profile fields so PDF still builds; `@react-pdf/renderer` one-page layout matching `context/templates/demo_resume.pdf` style (`lib/resume-pdf/DemoResumeDocument.tsx`), upload to `resumes/{user_id}/resume.pdf`, update `resume_pdf_url`, PostHog `resume_generated`. Shares Feature 07 user + IP rate pools (user pool skipped with BYOK; IP still applies); **usage hits only on successful generate**, same success-only rule as Extract.
- Features 09–13 Find Jobs / Details / Research: `/find-jobs` from `context/designs/find-jobs.png` under `components/find-jobs/` (AuthGuard + shared `Navbar`).
